Consider N objects placed in a multidimensional space and stored across a distributed network of C compute nodes. The problem is:
- how to divide the universe so that each compute node holds an equal number of objects `N/C`?
- how to keep the objects of each compute node as close as possible to each other?
- how to keep the regions of overlap of objects across compute nodes minimal or nonexistent? 

This problem setup is very common and highly important in large-scale scientific applications. A good spatial decomposition stores close objects in the same memory region (compute node), which reduces inter-node dependencies (communication).

The simplest spatial decomposition algorithms perform an orthogonal spatial decomposition (*slicing*). In a 2D space, several slicing layouts are possible:

The layouts differ in efficiency. Layout 1 leads to high object duplication when objects have volume (i.e. are not points in space) and the number of slices is high. Layout 2 reduces this cloning, but does not guarantee an accurate spatial decomposition. Layouts 3 and 4 are similar, but layout 4 allows for more parallelism. Layout 3 performs a tree-based recursive bisection (i.e. it computes 2 slices at every level of the tree), while layout 4 computes several slices at once for each of the 2 dimensions. 

The following table details the complexity of each algorithm, assuming sorting with an average complexity of $$ n \log n$$:

| Scheme | Computation steps | Properties / Limitations |
|:-:|:--|:--|
| <img width="70" height="70" src="{{ site.assets }}/slicing/mini-single-axis.svg"><br/>**Single Axis** | $$= n \cdot \log_2 n$$ | One sorting of all elements on a single direction, independently of the number of dimensions. |
| <img width="70" height="70" src="{{ site.assets }}/slicing/mini-nug.svg"><br/>**Non-Uniform Grid** | $$= d \cdot n \cdot \log_2 n$$ | One sorting of all elements applied to each dimension, iteratively; slicing configuration for the $$d$$ dimensions must decompose final number of slices $$s$$ i.e. $$\prod_{k=1}^d S_k = s$$. |
| <img width="70" height="70" src="{{ site.assets }}/slicing/mini-str.svg"><br/>**Sort Tile Recursive** | $$\begin{array}{l} = n \cdot \log_2 n \\ +n \cdot \log_2 \frac{n}{S_1} \\ +n \cdot \log_2 \frac{n}{S_1 S_2} \\ +... \\ +n \cdot \log_2 \frac{n}{S_1 S_2 ... S_{d-1}} \\ = \sum_{i=1}^d n \cdot \log_2 \frac{n}{\prod_{k=0}^{i-1} S_k} \end{array}$$ | One sorting for each subslice's data on each dimension, applied iteratively; sub-slices computations are independent; slicing configuration for the $$d$$ dimensions must decompose final number of slices $$s$$ i.e. $$\prod_{k=1}^d S_k = s$$; Faster than NUG as each new dimension requires sorting across smaller datasets; we assume $$S_0 = 1$$ i.e. the initial universe is a single slice including all elements. |
| <img width="70" height="70" src="{{ site.assets }}/slicing/mini-orb.svg"><br/>**Orthogonal Recursive Bisection** | $$\begin{array}{l} = n \cdot \log_2 n \\ +n \cdot \log_2 \frac{n}{2} \\ +n \cdot \log_2 \frac{n}{4} \\ +n \cdot \log_2 \frac{n}{8} \\ +... \\ +n \cdot \log_2 \frac{n}{\log_2 s} \\ = \sum_{i=1}^{\log_2 s} n \cdot \log_2 \frac{n}{2^{i-1}} \end{array}$$ | Total number of slices $$s$$ must be a power of 2; requires one sorting of half of the elements of a slice per iteration for a total of $$\log_2 s$$ steps, therefore a slow method on large networks; sub-slices computations are independent. |

Among all slicing layouts, (4) is the most efficient: it guarantees low data duplication, allows for accurate slicing, and requires only D (dimensions) recursive iterations, regardless of the number of compute nodes (unlike (3)). However, its implementation in a distributed memory environment is not trivial. Possible options are:
- A histogram/binning algorithm that groups elements into spatial bins and uses the number of elements per bin as the slicing metric;
- A serial slicing on one compute node that holds only a sample of the data. The slicing of the sampled dataset is then used as the slicing of the full dataset.

## Distributed Slicing via Sort-Balance-Split
 
The *Sort-Balance-Split* (SBS) technique, published by the author in [this paper][slicing-ref], implements a parallel multi-dimensional slicing based on layout (4). The algorithm has three steps:
- The **sorting** step performs a distributed sort of all elements on a given dimension;
- The **load balancing** step equalizes the number of elements across compute nodes, while preserving the sort order;

{: .picture}
 <img width="54.2%" height="54.2%" src="{{ site.assets }}/slicing/balance.svg">

{: .caption}
Load balancing of 19 sorted elements on 3 ranks, colored by rank. The first 19 mod 3 = 1 rank holds one more element. The balance takes three collective operations: `MPI_Allgather` for the counts, `MPI_Alltoall` for the send counts and `MPI_Alltoallv` for the elements. Adapted from: [An Efficient Parallel Load-balancing Framework for Orthogonal Decomposition of Geometrical Data](https://link.springer.com/chapter/10.1007/978-3-319-41321-1_5)

- The **splitting step** creates smaller networks, called subnetworks, from subsets of the ranks of the main network.

{: .picture}
 <img width="60.2%" height="60.2%" src="{{ site.assets }}/slicing/split.svg">

{: .caption}
The split of 8 ranks into $$S_k = 2$$ and $$S_k = 4$$ subnetworks of consecutive ranks, after the sort and the balance, colored by rank. The data stays in place, and each rank gets a new rank in its subnetwork. The split is one collective operation, `MPI_Comm_split`. $$S_k$$ divides the number of ranks. Adapted from: [An Efficient Parallel Load-balancing Framework for Orthogonal Decomposition of Geometrical Data](https://link.springer.com/chapter/10.1007/978-3-319-41321-1_5)

These three steps give the method its name. SBS is applied recursively, and each level operates on the subnetworks created by the split step of the previous level.

The method is efficient and has two advantages over existing methods: (1) a fixed complexity, as the number of communication steps is fixed for any network and input size; and (2) an accurate spatial decomposition, i.e. not an approximation.

The following example applies the algorithm to a 2D universe of 16 shapes distributed across 4 compute nodes (ranks):

{: .picture}
<img width="94.3%" height="94.3%" src="{{ site.assets }}/slicing/str_steps.svg">

{: .caption}
Adapted from: [An Efficient Parallel Load-balancing Framework for Orthogonal Decomposition of Geometrical Data](https://link.springer.com/chapter/10.1007/978-3-319-41321-1_5)

From left to right:
1. Initial data layout;
2. The initial sort orders all elements on the first (X) dimension, ignoring the other coordinates. Data is then load balanced on the X axis, so that each rank holds 4 shapes;
3. A network split divides the initial problem of 16 shapes on a single network of 4 nodes into 2 problems of 8 shapes, each on a network of 2 nodes;
4. Each subnetwork performs a distributed sort of its objects on the next axis (Y), and balances the workload;
5. Final data layout.
