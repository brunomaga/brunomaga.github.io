Imagine you have N objects placed in a multidimensional space, stored across a distributed network of C compute nodes. The problem is simple:
- how to divide the universe in such a way that each compute node gets an equal number of objects `N/C`? and
- how to ensure that the objects of each compute node are as close as possible to each other? and
- how to ensure that the regions of overlap of objects across compute nodes are minimal or nonexistent? 

This is a very common problem setup, and one of high importance in large-scale scientific applications. The main rationale is that a good spatial decomposition should allow close objects to be stored in the same memory region (compute node), so that inter-node dependency (communication) is reduced.

The simplest spatial decomposition algorithms perform an orthogonal spatial decomposition (*slicing*). In a 2D space, there are several slicing alternatives:

A small note on efficiency. If you pick slicing layout 1, you will incur a lot of object duplication when objects are not points in space but have volume, and when there is a high number of slices. Layout 2 works better by reducing cloning, yet it does not guarantee an accurate spatial decomposition. Layouts 3 and 4 are similar, but layout 4 outperforms layout 3 in parallelism. This is because layout 3 performs a tree-based recursive bisectional decomposition (i.e. at every level of the tree it computes 2 slices), while layout 4 performs several slices at once for each of the 2 dimensions. 

The following table details the complexity of each algorithm (we assume sorting with an average complexity of $$ n \log n$$):

{: style="text-align:center; font-size: small;"}
<img width="70%" height="70%" src="{{ site.assets }}/slicing/table.png">

Across all possible slicing layouts, (4) is the most efficient: it guarantees low data duplication, allows for accurate slicing, and requires only D (dimensions) recursive iterations, regardless of the number of compute nodes (unlike (3)). However, its implementation in a distributed memory environment is not trivial. Possible options are:
- A histogram/binning algorithm that clusters elements in spatial bins and uses the number of elements per bin as the metric for slicing;
- A method that performs serial slicing on one compute node that holds only a sample of the data, and uses the slicing of the sampled dataset as the slicing of the final dataset.

## Distributed Slicing via Sort-Balance-Split
 
A technique I published in [this paper][slicing-ref], called the *Sort-Balance-Split* (SBS), implements a parallel multi-dimensional slicing based on the previous algorithm. The algorithm follows three steps:
- The **sorting** step performs a distributed sort of all elements on a given dimension. Distributed sorting algorithms were covered in depth in my [previous post][sorting-post];
- The **load balancing** step equalizes the number of elements across compute nodes, while respecting the initial sorting;

{: style="text-align:center; font-size: small;"}
 <img width="70%" height="70%" src="{{ site.assets }}/slicing/balance.svg">

- The **splitting step** creates smaller networks, which we will call subnetworks, from subsets of the ranks of the main network.

{: style="text-align:center; font-size: small;"}
 <img width="70%" height="70%" src="{{ site.assets }}/slicing/split.svg">

The three steps explain the name Sort-Balance-Split. We perform the SBS algorithm recursively at every level, where each level operates on the subnetworks created by the split step.

This method has several advantages over existing methods, while delivering an efficient execution: (1) a fixed complexity, as the number of communication steps is fixed for any network and input size; and (2) an accurate spatial decomposition, i.e. not an approximation.

A sample application of the algorithm on a 2D universe of 16 shapes distributed across 4 compute nodes (ranks) is presented below:

{: style="text-align:center; font-size: small;"}
<img width="80%" height="80%" src="{{ site.assets }}/slicing/str_steps.svg">

From left to right:
1. Initial data layout;
2. The initial sorting operation sorts all elements on the first (X) dimension, without caring about the other coordinates. Data is load balanced on the X axis, so that each rank holds 4 shapes;
3. A network split divides the initial problem of 16 shapes across 4 nodes on a single network into 2 problems of 8 shapes, each on a network of 2 nodes;
4. Each network performs a distributed sort of its objects on the next axis (Y), and balances the workload;
5. Final data layout.
