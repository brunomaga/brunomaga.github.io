In 2017, the paper [Attention Is All You Need](https://arxiv.org/abs/1706.03762) (Vaswani et al.) introduced the [transformer](https://en.wikipedia.org/wiki/Transformer_(deep_learning_architecture)), a translation model built on attention instead of the recurrence of [recurrent neural networks](https://en.wikipedia.org/wiki/Recurrent_neural_network). It handles the dependencies between the tokens of a sequence by learning an attention matrix that exposes every token to all the other tokens. Like other translation models, it has two parts: an encoder, which learns the structure of the source language, and a decoder, which learns to translate into the target language. The main difference between the two is the *mask* in the attention of the decoder, which hides the tokens that come later in the sequence, so that the prediction of the next token depends only on the tokens before it. The [transformer post]({{ site.baseurl }}{% post_url 2020-02-28-learning-from-sequences %}) describes the model in detail.

The transformer soon proved useful well beyond translation. It applies to many types of data, such as time series and images, and its blocks can be stacked into deep models: most large language models today are stacks of transformer blocks. [BERT]({{ site.baseurl }}{% post_url 2020-02-28-learning-from-sequences %}#bert-bidirectional-encoder-representations-from-transformers), for example, is a stack of encoders, used for classification and regression. A stack of decoders, without the encoder and the cross-attention that connects the decoder to it, is a [language model](https://en.wikipedia.org/wiki/Language_model): it predicts the next token of a text, and generates text one token at a time. [GPT-2](https://en.wikipedia.org/wiki/GPT-2) and its successors follow this design, and so does GPTlite, the small model that the rest of the post builds in PyTorch and trains on a text of Shakespeare's plays. The figure shows how its blocks differ from those of the transformer.

## Hyperparameters

The code starts with the imports and the hyperparameters of the training, set to small values for a first run:

```python
import torch

import torch.nn.functional as F

torch.manual_seed(42)

# device: where to execute computation
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

# how often to do an evaluation step
eval_interval = 100

# number of training iterations
max_iters = 500

# optimizer's learning rate
learning_rate=1e-4

# minibatch size, how many inputs to 'pack' per iteration 
batch_size = 3
```

The hyperparameters of the model follow, where `block_size` is the length of the context, the maximum number of tokens that the model reads at once:

```python

# block size is the maximum sequence length used as input.

block_size = 4

# size of the embeddings
n_embd = 16

# number of attention heads in the multi-head attention mechanism
n_head = 4

# depth of the network as number of decoder blocks (the Nx in the GPT decoder diagram).
# Each block contains a normalization, an attention and a feed forward unit

# dropout rate (variable p) for dropout units
dropout = 0.2
```

## Tokenization

A neural network computes with numbers, so a *tokenizer* first turns the text into a sequence of integers, the *tokens*, and an embedding then maps each token to a learned vector of size $$E$$ (`n_embd`). The simplest tokenizer maps each character to an integer:

```python
# collect sorted list of input characters and create 
# string-to-int (stoi) and int-to-string (itos) representations:
chars = sorted(list(set(text)))
stoi = { ch:i for i,ch in enumerate(chars) }
itos = { i:ch for i,ch in enumerate(chars) }

# define encode and decode functions that convert strings to arrays of tokens and vice-versa
encode = lambda x: torch.tensor([stoi[ch] for ch in x], dtype=torch.long) #encode text to integers
decode = lambda x: ''.join([itos[i] for i in x]) #decode integers to text
vocab_size = len(stoi)
``` 

The vocabulary size `vocab_size` is the number of distinct tokens, here the 65 characters of the text, of which the first is the line break `\n`:

```python

!$&',-.3:;?ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz
```

Packing several characters into each token, as a tokenizer of words or subwords does, is a trade-off. The vocabulary is larger, and so are the embedding table and the output layer, which have one row per token. In exchange, a text becomes a shorter sequence of tokens, so that a context of `block_size` tokens covers more text, and attention, whose cost grows with the square of the sequence length, runs on fewer tokens. Examples are Google's [SentencePiece](https://github.com/google/sentencepiece), the tokenizers of [Hugging Face](https://huggingface.co/docs/transformers/tokenizer_summary), and `tiktoken`, the [byte-pair encoding](https://en.wikipedia.org/wiki/Byte-pair_encoding) (BPE) tokenizer of OpenAI's GPT models:

```python
import tiktoken
enc = tiktoken.encoding_for_model("gpt-4")
print(enc.n_vocab)
print(enc.encode("Hello world"))
print(enc.decode(enc.encode("Hello world")))
```

The output is the vocabulary size of the GPT-4 tokenizer, 100,277, the tokens of `"Hello world"`, `[9906, 1917]`, only two for 11 characters, and the decoded string.

## Positional Encodings

Attention by itself has no notion of order. Without a mask, it is permutation-equivariant: permuting the input tokens permutes its outputs in the same way. The model therefore adds a position embedding to each token embedding, so that it can use the order of the tokens. The transformer uses a fixed encoding made of sines and cosines, which the [transformer post]({{ site.baseurl }}{% post_url 2020-02-28-learning-from-sequences %}#embeddings-and-positional-encoding) details. For simplicity, GPTlite learns its position embeddings instead, as GPT-2 does, with an `nn.Embedding` table of `block_size` rows. The price is that a learned table has no entry beyond position `block_size`, while the sines and cosines are defined for any position.

```python
token_embedding_table = nn.Embedding(vocab_size, n_embd)    # from tokens to embedding
position_embedding_table = nn.Embedding(block_size, n_embd) # from position to embedding
```

## Batching

The text is split into 90% of training data and 10% of validation data, which show how well the model predicts a text it was not trained on:

```python
data = encode(text)  #use any encoder here
n = int(0.9*len(data))
train_data, valid_data = data[:n], data[n:]
```

The full, training and validation sets have 1,115,394, 1,003,854 and 111,540 tokens.

The model must learn to predict the next token from contexts of every length, from 1 to `block_size` tokens, and a single window of text provides all of them. Each sample of a batch is a window of `block_size` consecutive tokens at a random offset, and its target is the same window shifted by one token. Thanks to the causal mask, the output at position $$t$$ sees only the tokens $$0$$ to $$t$$ and predicts the token $$t+1$$, so that one sample holds `block_size` training examples:

```python
def get_batch(source):
  """ get a batch of batch_size sequences of length block_size from source """
  
  # generate `batch_size` random offsets on the data 
  ix = torch.randint(len(source)-block_size, (batch_size,) )
  # collect `batch_size` subsequences of length `block_size` from source, as data and target
  x = torch.stack([source[i:i+block_size] for i in ix])
  # target is just x shifted right (ie the predicted token is the next in the sequence)
  y = torch.stack([source[i+1:i+1+block_size] for i in ix])
  return x.to(device), y.to(device)


# test get_batch()
xb, yb = get_batch(train_data)
print("input:\n",xb)
print("target:\n",yb)

for b in range(batch_size): #for every batches
  print(f"\n=== batch {b}:")
  for t in range(block_size): #for each sequence in block
    context = xb[b,:t+1]
    target = yb[b,t]
    print(f"for input {context.tolist()} target is {target.tolist()}")
```

## Multi-Head Masked Attention

Attention computes each token of its output as a weighted average of the tokens of its input. Row $$t$$ of the attention matrix holds the weights with which token $$t$$ averages the tokens of the sequence, i.e. how much each of them matters to it. The causal mask lets each token see only itself and the previous tokens, so the matrix is lower triangular, and the simplest matrix of this kind gives the same weight to all the visible tokens. For a random input `x` of shape (batch, sequence, embedding):

```python
B, S, E, = 4, 8, 2
x = torch.randn(B,S,E) #shape (B,S,E)
```

The code writes the dimensions as:
- `B`, the batch size, `batch_size`;
- `S`, the sequence length, at most `block_size`;
- `E`, the embedding size, `n_embd`;
- `C`, the vocabulary size, `vocab_size`.

The uniform attention matrix keeps the lower triangle of a matrix of ones, and divides each row by its sum:

```python
#attention matrix (lower triangular), a mask used to only show previous items to predict next item
wei = torch.tril(torch.ones((S,S), dtype=torch.float32, device=device))
#normalize mask so that it sums to one. use keepdim to make broadcast operation work later
wei /= wei.sum(dim=1, keepdim=True)
``` 

An equivalent notation, used below, sets the masked entries to $$-\infty$$ and applies a [softmax](https://en.wikipedia.org/wiki/Softmax_function) to each row. The exponential of $$-\infty$$ is zero, so the masked entries get no weight, and the visible entries of a row, being equal, get equal weights:

```python
tril = torch.tril(torch.ones(S,S))
wei = wei.masked_fill(tril==0, float('-inf'))
wei = F.softmax(wei, dim=-1) #equivalent to the normalization above
```

Both give the following `wei`, whose rows sum to 1:

```python
tensor([[1.0000, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000],
        [0.5000, 0.5000, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000],
        [0.3333, 0.3333, 0.3333, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000],
        [0.2500, 0.2500, 0.2500, 0.2500, 0.0000, 0.0000, 0.0000, 0.0000],
        [0.2000, 0.2000, 0.2000, 0.2000, 0.2000, 0.0000, 0.0000, 0.0000],
        [0.1667, 0.1667, 0.1667, 0.1667, 0.1667, 0.1667, 0.0000, 0.0000],
        [0.1429, 0.1429, 0.1429, 0.1429, 0.1429, 0.1429, 0.1429, 0.0000],
        [0.1250, 0.1250, 0.1250, 0.1250, 0.1250, 0.1250, 0.1250, 0.1250]])
```

The product of `wei` and `x` is the output of the attention, whose row $$t$$ is the average of the tokens $$0$$ to $$t$$:

```python
out = wei @ x   # dot product shape: (B,S,S) @ (B,S,E) = (B,S,E) ie ([4, 8, 2])
```

Both `x` and `out` have the shape `[B, S, E]`, here `[4, 8, 2]`.

A plain average treats all the previous tokens alike, while some of them matter much more than others, so self-attention computes the weights from the input itself. The transformer paper defines the multi-head attention as:

$$
\mathrm{MultiHead}(Q, K, V) = \mathrm{Concat}(\mathrm{head}_1, \dots, \mathrm{head}_h) \, W^O
$$

$$
\text{where } \mathrm{head}_i = \mathrm{Attention}(Q W^Q_i, K W^K_i, V W^V_i)
$$

$$
\text{and } \mathrm{Attention}(Q, K, V) = \mathrm{softmax}\left( \frac{Q K^T}{\sqrt{d_k}} \right) V
$$

where $$h$$ is the number of heads, `n_head`, and $$d_k$$ is the size of a head, `head_size`. Each head projects the input into queries, keys and values, and the dot product of a query and a key, their score, says how much the token of the query attends to the token of the key. In self-attention, $$Q$$, $$K$$ and $$V$$ are all the input `x`.

<img width="25.2%" height="25.2%" src="{{ site.assets }}/gptlite/gptlite_attention.svg"/>

{: .caption}
The multi-head attention module in the GPTlite model, emphasized in red. Adapted from: [Attention Is All You Need](https://arxiv.org/abs/1706.03762).

The projections $$W^Q$$, $$W^K$$ and $$W^V$$ of a head are linear layers without bias:

```python
head_size=4
key   = nn.Linear(E, head_size, bias=False) 
query = nn.Linear(E, head_size, bias=False)
value = nn.Linear(E, head_size, bias=False)
```

The scaled scores $$Q K^T / \sqrt{d_k}$$ are:

```python
k = key(x) #shape (B,S, head_size)
q = query(x) #shape (B,S, head_size)
wei = q @ k.transpose(-2, -1) #shape (B,S, head_size) @ (B,head_size,S) = (B,S,S)
wei *= head_size**-0.5 #scale by sqrt(d_k) as per paper, so that variance of the wei is 1
```

The mask and the softmax of the uniform case then turn the scores into weights, which average the values `v`:

```python
tril = torch.tril(torch.ones(S,S))
wei = wei.masked_fill(tril==0, float('-inf')) #tokens only "talk" to previous tokens
wei = F.softmax(wei, dim=-1) #equivalent to the normalization above (-inf in upper diagonal will be 0)
v = value(x) # shape (B,S, head_size)
out = wei @ v # shape (B,S,S) @ (B,S,head_size) --> (B,S,head_size)
```

The weights are no longer uniform: they come from learned projections of the input, and differ from one query to the next. This is the main property of self-attention: in the uniform matrix, every token was a plain average of the previous tokens, while here each token weighs them by their importance to it.

The scaling by $$1/\sqrt{d_k}$$ keeps the scores in a useful range. For independent query and key components with zero mean and unit variance, the dot product of a query and a key has the variance $$d_k$$. Without the scaling, the scores of large heads would be large, and the softmax of large scores is close to a [one-hot](https://en.wikipedia.org/wiki/One-hot) vector, whose gradients are close to zero. The scaling brings the variance back to 1, and gives a more diffuse distribution of the weights.

Attention is more general than this. In *cross-attention*, the queries come from one sequence, and the keys and the values from another, such as the output of an encoder; GPTlite has no encoder, so it uses only self-attention. The mask also depends on the task: models that encode or classify a whole sequence, such as the string representation of a chemical compound or a sentence for sentiment analysis, use no mask, and a band around the diagonal lets each token see only its closest neighbours. Whatever the mask, attention never mixes the samples of a batch.

The `Head` module computes one head, and `MultiHeadAttention` runs `n_head` heads in parallel, concatenates their outputs, and maps them back to the size $$E$$ with the projection $$W^O$$ (`proj`):

```python
class Head(nn.Module):

  def __init__(self, head_size):
    super().__init__()
    self.key   = nn.Linear(n_embd, head_size, bias=False)
    self.query = nn.Linear(n_embd, head_size, bias=False)
    self.value = nn.Linear(n_embd, head_size, bias=False)
    self.head_size = head_size
    self.register_buffer('tril', torch.tril(torch.ones(block_size, block_size)))
    self.dropout = nn.Dropout(dropout)
    #Note: this dropout randomly prevents some tokens from communicating with each other

  def forward(self, x):
    B,S,_ = x.shape
    k = self.key(x) #shape (B,S, head_size)
    q = self.query(x) #shape (B,S, head_size)
    v = self.value(x) #shape (B,S, head_size)

    #compute self-attention scores
    wei = q @ k.transpose(-2, -1) #shape (B,S, head_size) @ (B,head_size,S) --> (B,S,S)
    wei *= self.head_size**-0.5 #scale by sqrt(d_k) as per paper, so that variance of the wei is 1
    wei = wei.masked_fill(self.tril[:S,:S]==0, float('-inf')) # (B,S,S)
    wei = F.softmax(wei, dim=-1) # (B, S, S)
    wei = self.dropout(wei)

    #perform weighted aggregation of values
    out = wei @ v # (B, S, S) @ (B, S, head_size) --> (B, S, head_size)
    return out
```

```python
class MultiHeadAttention(nn.Module):
  """ Multi-head attention as a collection of heads with concatenated outputs."""
  def __init__(self, num_heads, head_size):
    super().__init__()
    self.heads = nn.ModuleList([Head(head_size) for _ in range(num_heads)])
    self.proj  = nn.Linear(head_size*num_heads, n_embd) # combine all head outputs
    self.dropout = nn.Dropout(dropout)

  def forward(self, x):
    out = torch.cat([head(x) for head in self.heads], dim=-1)
    out = self.proj(out)
    out = self.dropout(out)
    return out
```

## Feed-Forward Network

While attention mixes the information of different tokens, the feed-forward network (FFN) that follows it processes each token separately. It is a neural network with one hidden layer of size $$4E$$ and a ReLU activation:

```python
class FeedForward(nn.Module):
  """ the feed forward network (FFN) in the paper"""

  def __init__(self, n_embd):
    super().__init__()
    # Note: in the paper (section 3.3) we have d_{model}=512 and d_{ff}=2048.
    # Therefore the inner layer is 4 times the size of the embedding layer
    self.net = nn.Sequential(
        nn.Linear(n_embd, n_embd*4),
        nn.ReLU(),
        nn.Linear(n_embd*4, n_embd),
        nn.Dropout(dropout)
      )

  def forward(self, x):
    return self.net(x)
```

The FFN has $$8E^2$$ weights, and the four projections of the attention, $$W^Q$$, $$W^K$$, $$W^V$$ and $$W^O$$, have $$4E^2$$ in total, so the FFN holds two thirds of the weights of a block.

## The GPT Block

A GPT block applies a multi-head attention and then an FFN, and two details make a deep stack of such blocks trainable. The first is a [residual connection](https://en.wikipedia.org/wiki/Residual_neural_network) around each of the two sublayers, which adds the input of the sublayer to its output, so that the gradients flow directly through the stack. The second is the [layer normalization](https://en.wikipedia.org/wiki/Normalization_(machine_learning)#Layer_normalization), which normalizes the vector of each token to zero mean and unit variance. The transformer paper applies it after the residual addition, $$\mathrm{LayerNorm}(x + \mathrm{Sublayer}(x))$$ (post-norm), while GPT-2 and most later models apply it to the input of each sublayer, $$x + \mathrm{Sublayer}(\mathrm{LayerNorm}(x))$$ (pre-norm), and add a layer normalization after the last block. With pre-norm, the gradients are well behaved at initialization, and training reaches comparable results without the learning-rate warm-up that post-norm needs ([On Layer Normalization in the Transformer Architecture](https://arxiv.org/abs/2002.04745), Xiong et al., 2020). GPTlite uses pre-norm:

```python
class Block(nn.Module):
  """ Transformer block: communication (attention) followed by computation (FFN) """

  def __init__(self, n_embd, n_head):
    # n_embd: embedding dimension
    # n_head: the number of heads we'd like to use
    super().__init__()
    head_size = n_embd // n_head
    self.sa = MultiHeadAttention(n_head, head_size)
    self.ffwd = FeedForward(n_embd)
    self.ln1 = nn.LayerNorm(n_embd)
    self.ln2 = nn.LayerNorm(n_embd)

  def forward(self, x):
    x = x + self.sa(self.ln1(x))
    x = x + self.ffwd(self.ln2(x))
    return x
```

## Final Model

Putting it all together, the model sums the token and the position embeddings, applies the `n_layer` blocks and the final layer normalization, and maps each position to `vocab_size` logits, the scores of the possible next tokens, with a linear layer:

```python
class GPTlite(nn.Module):

  def __init__(self, vocab_size):
    super().__init__()
    
    # vocabulary embedding and positional embedding
    self.token_embedding_table = nn.Embedding(vocab_size, n_embd)
    self.position_embedding_table = nn.Embedding(block_size, n_embd)

    #sequence of attention heads and feed forward layers
    self.blocks = nn.Sequential( *[Block(n_embd, n_head) for _ in range(n_layer)])

    #one layer normalization layer after transformer blocks
    #and one before linear layer that outputs the vocabulary
    self.ln = nn.LayerNorm(n_embd)
    self.lm_head = nn.Linear(n_embd, vocab_size, bias=False)


  def forward(self, idx):
    """ call the model with idx, for training or generation """

    #idx is of shape (B,S)
    B, S = idx.shape
    tok_emb = self.token_embedding_table(idx) #shape (B,S,E)
    pos_emb = self.position_embedding_table(torch.arange(S, device=idx.device)) #shape (S,E)
    x = tok_emb + pos_emb #shape (B,S,E)
    x = self.blocks(x)
    x = self.ln(x)
    logits = self.lm_head(x) #shape (B,S,C)
    logits = torch.swapaxes(logits, 1, 2) #shape (B,C,S) to comply with CrossEntropyLoss
    return logits
```

Generation is a loop. At each step, the model reads the last `block_size` tokens, as many as its position embeddings allow, a softmax turns the logits of the last position into probabilities, and the next token, sampled from these probabilities, is appended to the sequence:

```python
  def generate(self, idx, max_new_tokens):
    """ given a context idx, generate max_new_tokens tokens and append them to idx """
    for _ in range(max_new_tokens):
      idx_cond = idx[:, -block_size:] #we can never have any idx longer than block_size
      logits = self(idx_cond) #call fwd without targets
      logits = logits[:, :, -1] # take last token. from shape (B, C, S) to (B, C)
      #convert logits to probabilities
      probs = F.softmax(logits, dim=-1) # shape (B, C)
      #randomly sample the next tokens, 1 for each of the previous probability distributions
      #(one could take instead the argmax, but that would be deterministic and boring)
      idx_next = torch.multinomial(probs, num_samples=1) # shape (B, 1)
      #append next token ix to the solution sequence so far
      idx = torch.cat([idx, idx_next], dim=-1) # shape (B, S+1)
    return idx  
```

## Training Loop

The model is created on the compute device:

```python
m  = GPTlite(vocab_size).to(device)
```

Each training step computes the [cross-entropy](https://en.wikipedia.org/wiki/Cross-entropy) loss of the next tokens on a batch, and lets the [Adam](https://en.wikipedia.org/wiki/Stochastic_gradient_descent#Adam) optimizer update the weights. Every `eval_interval` steps, the loop also computes the loss of a validation batch:

```python
# train the model
optimizer = torch.optim.Adam(m.parameters(), lr=learning_rate)
for steps in range(max_iters):
  idx, targets = get_batch(train_data)   #get a batch of training data
  logits = m(idx)   #forward pass
  loss = F.cross_entropy(logits, targets)
  loss.backward()   #backward pass
  optimizer.step()   #update parameters
  optimizer.zero_grad(set_to_none=True)  #sets to None instead of 0, to save memory

  #print progress
  if steps % 100 == 0: print(f"step {steps}, loss {loss.item():.2f}")
    
  @torch.no_grad()
  # eval loop: no backprop on this data, to avoid storing all intermediate variables
  def eval_loss():
    idx, targets = get_batch(valid_data)   #get a batch of validation data
    logits = m(idx)   #forward pass
    loss = F.cross_entropy(logits, targets)
    print(f"step {steps}, eval loss {loss.item():.2f}")
    return loss
  
  if steps % eval_interval == 0: eval_loss().item()
      
```

Real models follow the same design at a much larger scale. GPT-3 ([Language Models are Few-Shot Learners](https://arxiv.org/abs/2005.14165), Brown et al., 2020) is a decoder-only transformer with 96 blocks, $$E = 12288$$, 96 heads, a context of 2048 tokens and 175 billion parameters. GPTlite also covers only pre-training, the first of the four steps that train a chat model. The other three are supervised fine-tuning, reward modeling, and reinforcement learning with PPO ([Proximal Policy Optimization Algorithms](https://arxiv.org/abs/1707.06347), Schulman et al., 2017), as in [Training language models to follow instructions with human feedback](https://arxiv.org/abs/2203.02155) (Ouyang et al., 2022). The talk [State of GPT](https://www.youtube.com/watch?v=bZQun8Y4L2A) gives an overview of the four steps.

The code follows the [tutorial video](https://www.youtube.com/watch?v=kCc8FmEb1nY) of Andrej Karpathy, whose [nanoGPT repo](https://github.com/karpathy/nanoGPT) trains GPT-2 models. The [GPTlite repo](https://github.com/{{ site.repository }}/tree/master/assets/gptlite) holds the full code, in an extended version where one projection computes all the heads at once, and where `main.py` clips the gradients and evaluates the model without dropout.
