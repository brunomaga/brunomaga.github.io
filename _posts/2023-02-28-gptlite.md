In 2017, the paper [Attention is all you need](https://arxiv.org/abs/1706.03762) introduced the Transformer model. The Transformer is a translation model based on an attention mechanism that is not recurrent (unlike RNNs). Instead, it handles the dependencies among tokens in a sequence by learning an attention matrix that *exposes* every token to all other tokens. Like other translation methods, it has two main components: an encoder that learns the structure of the source language, and a decoder that learns how to translate into the target language. The fundamental difference between the encoder and the decoder is the *mask* in the decoder's attention matrix. This mask hides the subsequent tokens of a sequence during decoding, so that the prediction of the next token is computed only from previous tokens.

The Transformer soon proved to have much more to offer. It can be applied to many data types (time series, images, etc.) and, most importantly, its components can be *stacked* as a sequence of blocks to perform higher-level cognitive tasks. As a result, the Transformer is now the base model of most large, best-performing ML models. One example is [BERT]({{ site.baseurl }}{% post_url 2020-02-28-learning-from-sequences %}), a stack of Transformer encoders used for regression and classification tasks. 

This post details the implementation of a large model based on a stack of decoder-only modules, *a la [GPT-2](https://en.wikipedia.org/wiki/GPT-2)*, used to generate long sentences from a given input.

## Tokenization

An embedding maps input characters to a numerical representation of *tokens*. There are several possible *tokenizers*. The simplest one maps each character directly to an integer:

```python
# collect sorted list of input characters and create 
# string-to-int (stoi) and int-to-string (itos) representations:
chars = sorted(list(set(text)))
stoi = { ch:i for i,ch in enumerate(chars) }
itos = { i:ch for i,ch in enumerate(chars) }

# define encode and decode functions that convert strings to arrays of tokens and vice-versa
encode = lambda x: torch.tensor([stoi[ch] for ch in x], dtype=torch.long) #encode text to integers
decode = lambda x: ''.join([itos[i] for i in x]) #decode integers to text
vocab_size = len(stoi)
``` 

The vocabulary size `vocab_size` is the number of distinct tokens, in this case `65` characters:
```python

!$&',-.3:;?ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz
```

, where the first character is the line break `\n`.

## Batching and dimensionality

The data is first split into 90% training and 10% validation data:

```python

train_data, valid_data = data[:n], data[n:]
```

For this input, the full, train and validation datasets have `1115394`, `1003854` and `111540` elements, respectively.

Batching in the attention mechanism is tricky. The model must accept a batch of several inputs, each with a maximum size of `block_size`. To allow this, the dataset includes, for a given input, all sequences from size `1` to size `block_size`. For each input sequence from position `0` to `t`, the target output is the element in position `t+1`. The following code illustrates this logic:    

```python
def get_batch(source):
  """ get a batch of batch_size sequences of length block_size from source """
  
  # generate `batch_size` random offsets on the data 
  ix = torch.randint(len(source)-block_size, (batch_size,) )
  # collect `batch_size` subsequences of length `block_size` from source, as data and target
  x = torch.stack([source[i:i+block_size] for i in ix])
  # target is just x shifted right (ie the predicted token is the next in the sequence)
  y = torch.stack([source[i+1:i+1+block_size] for i in ix])
  return x.to(device), y.to(device)


# test get_batch()

    context = xb[b,:t+1]
    target = yb[b,t]
    print(f"for input {context.tolist()} target is {target.tolist()}")
```

## Multi-Head Masked Attention

The attention mask defines which elements are "visible" to other elements in the attention matrix, and by how much. A common example is a lower-triangular attention matrix, which presents to each row (token) the current and previous tokens in the sentence. Each value in the attention matrix holds the "importance" of the column token, relative to all other columns of that row, when the row token makes a decision. Thus, the simplest attention matrix assigns uniform weights across each row, so that all tokens have the same weight/importance:

Consider a random input value `x` (of shape batch x sequence x embedding):
```python
B, S, E, = 4, 8, 2
x = torch.randn(B,S,E) #shape (B,S,E)
```

For simplicity, the following letters denote the shapes of arrays:
- size `E` for the *embedding size* of each token, defined above by `n_embd`;
- size `B` for the *batch size*, defined above by `batch_size`;
- size `S` for the *sequence* dimension, or input sequence length, defined by `block_size`.  

A *uniform* attention matrix is computed as:
```python
#attention matrix (lower triangular), a mask used to only show previous items to predict next item
wei = torch.tril(torch.ones((S,S), dtype=torch.float32, device=device))
#normalize mask so that it sums to one. use keepdim to make broadcast operation work later
wei /= wei.sum(dim=1, keepdim=True)
``` 

or, in an alternative notation (useful later), as:
```python
tril = torch.tril(torch.ones(S,S))
wei = wei.masked_fill(tril==0, float('-inf'))
wei = F.softmax(wei, dim=-1) #equivalent to the normalization above
```

Both notations output the following `wei`:

```python
tensor([[1.0000, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000],
        [0.5000, 0.5000, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000],
        [0.3333, 0.3333, 0.3333, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000],
        [0.2500, 0.2500, 0.2500, 0.2500, 0.0000, 0.0000, 0.0000, 0.0000],
        [0.2000, 0.2000, 0.2000, 0.2000, 0.2000, 0.0000, 0.0000, 0.0000],
        [0.1667, 0.1667, 0.1667, 0.1667, 0.1667, 0.1667, 0.0000, 0.0000],
        [0.1429, 0.1429, 0.1429, 0.1429, 0.1429, 0.1429, 0.1429, 0.0000],
        [0.1250, 0.1250, 0.1250, 0.1250, 0.1250, 0.1250, 0.1250, 0.1250]])
```

The `wei` matrix indicates how much *attention* each token gives to itself and to previous tokens, normalized to 1. In this case, the attention is uniform.
The output of the attention head for the given `x` is the dot product of the attention `wei` and the input `x`:

```python
out = wei @ x   # dot product shape: (B,S,S) @ (B,S,E) = (B,S,E) ie ([4, 8, 2])
```

Both `x` and `out` have dimensionality `[B, S, E]`, i.e. `[4, 8, 2]`.  
 
The next step is a non-uniform attention matrix. The original paper formulates attention as:

$$
MultiHead(Q, K, V ) = Concat(head_1, ..., head_h)W^O
$$

$$
\text{where } head_i = Attention(QW^Q_i, KW^K_i, VW^V_i)
$$

$$
\text{where } Attention(Q,K,V) = softmax \left( \frac{QK^T}{\sqrt{d_k}} \right) \, V
$$


{: style="text-align:center; font-size: small;"}
<img width="24%" height="24%" src="{{ site.assets }}/gptlite/gptlite_attention.svg"/>

{: style="text-align:center; font-size: small;"}
The multi-head (Nx) attention module in the GPTlite model, emphasized in red. Adapted from [Attention is all you need](https://arxiv.org/abs/1706.03762).


The $$W^Q$$, $$W^K$$ and $$W^V$$ matrices are computed as simple projections (*linear layers*):

```python
head_size=4
key   = nn.Linear(E, head_size, bias=False) 
query = nn.Linear(E, head_size, bias=False)
value = nn.Linear(E, head_size, bias=False)
```

The $$Attention(Q,K,V)$$ is then computed as:

```python
k = key(x) #shape (B,S, head_size)
q = query(x) #shape (B,S, head_size)
wei = q @ k.transpose(-2, -1) #shape (B,S, head_size) @ (B,head_size,S) = (B,S,S)
wei *= head_size**-0.5 #scale by sqrt(d_k) as per paper, so that variance of the wei is 1
```

The output of the non-uniform attention matrix is computed by adapting the (alternative) notation of the uniform attention above:
```python
tril = torch.tril(torch.ones(S,S))
wei = wei.masked_fill(tril==0, float('-inf')) #tokens only "talk" to previous tokens
wei = F.softmax(wei, dim=-1) #equivalent to the normalization above (-inf in upper diagonal will be 0)
v = value(x) # shape (B,S, head_size)
out = wei @ v # shape (B,S,S) @ (B,S,head_size) --> (B,S,head_size)
```

Note that `out = wei @ x` is the same inner dot product as before, but the attention weights are no longer uniform: they are computed from learnt parameters and change per query and over time. **This is the main property and the main problem that self-attention solves: non-uniform attention weights per query**. In the uniform attention matrix, the weights were equal across all previous tokens, i.e. the aggregation was a plain average of all tokens in the sequence. Here, tokens are aggregated by a "value of importance" for each token.

Without the $$\sqrt{d_k}$$ normalization, the values in `wei` would have a high variance, and the softmax would approximate a one-hot vector. The normalization creates a more diffuse (less sparse) `wei` vector.

This mechanism is called *self-attention* because $$K$$, $$Q$$ and $$V$$ all come from the same input `x`. Attention is more general: `x` can be given by a data source, and $$K$$, $$Q$$ and $$V$$ may come from different sources. This is called *cross-attention*.

Elements across batches are always independent, i.e. there is no cross-batch attention. In many use cases, e.g. string representations of chemical compounds or sentiment analysis, there is no attention mask (i.e. all tokens attend to all tokens), or there is a custom mask that fits the use case (e.g. the main, upper and lower diagonals, so that tokens see only their closest neighbours). Also, this model has no cross-attention between the encoder and decoder.

The decoder includes a multi-head attention, which concatenates the outputs of the individual heads. The `Head` and `MultiHeadAttention` modules are implemented as:

```python
class Head(nn.Module):

  def __init__(self, head_size):
    super().__init__()
    self.key   = nn.Linear(n_embd, head_size, bias=False)
    self.query = nn.Linear(n_embd, head_size, bias=False)
    self.value = nn.Linear(n_embd, head_size, bias=False)
    self.register_buffer('tril', torch.tril(torch.ones(block_size, block_size)))
    self.dropout = nn.Dropout(dropout)
    #Note: this dropout randomly prevents some tokens from communicating with each other

  def forward(self, x):
    B,S,E = x.shape
    k = self.key(x) #shape (B,S, head_size)
    q = self.query(x) #shape (B,S, head_size)
    v = self.value(x) #shape (B,S, head_size)

    #compute self-attention scores
    wei = q @ k.transpose(-2, -1) #shape (B,S, head_size) @ (B,head_size,S) --> (B,S,S)
    wei *= E**-0.5 #scale by sqrt(d_k) as per paper, so that variance of the wei is 1
    wei = wei.masked_fill(self.tril[:S,:S]==0, float('-inf')) # (B,S,S)
    wei = F.softmax(wei, dim=-1) # (B, S, S)
    wei = self.dropout(wei)

    #perform weighted aggregation of values
    out = wei @ v # (B, S, S) @ (B, S, head_size) --> (B, S, head_size)
    return out
```

```python
class MultiHeadAttention(nn.Module):
  """ Multi-head attention as a collection of heads with concatenated outputs."""
  def __init__(self, num_heads, head_size):
    super().__init__()
    self.heads = nn.ModuleList([Head(head_size) for _ in range(num_heads)])
    self.proj  = nn.Linear(head_size*num_heads, n_embd) # combine all head outputs
    self.dropout = nn.Dropout(dropout)

  def forward(self, x):
    out = torch.cat([head(x) for head in self.heads], dim=-1)
    out = self.proj(out)
    out = self.dropout(out)
    return out
```

## Feed Forward Network


The feed-forward network (FFN) in the decoder is a Deep Neural Network with a single hidden layer:

```python
class FeedForward(nn.Module):
  """ the feed forward network (FFN) in the paper"""

  def __init__(self, n_embd):
    super().__init__()
    # Note: in the paper (section 3.3) we have d_{model}=512 and d_{ff}=2048.
    # Therefore the inner layer is 4 times the size of the embedding layer
    self.net = nn.Sequential(
        nn.Linear(n_embd, n_embd*4),
        nn.ReLU(),
        nn.Linear(n_embd*4, n_embd),
        nn.Dropout(dropout)
      )

  def forward(self, x):
    return self.net(x)
```

## The GPT Block

A GPT *block* is the sequence of a multi-head attention and a feed-forward module. Two subtle improvements are worth noting. First, a high number of sequential blocks makes the network too deep and hard to train, so each block includes skip connections. Second, the original paper applies layer normalization *after* the attention and the feed-forward network, and after adding the skip connection. Nowadays, it is common to use the *pre-norm formulation* instead, where normalization is applied before the attention and the FFN. The following code uses the pre-norm formulation: 

```python
class Block(nn.Module):
  """ Transformer block: communication (attention) followed by computation (FFN) """

  def __init__(self, n_embd, n_head):
    # n_embd: embedding dimension
    # n_head: the number of heads we'd like to use
    super().__init__()
    head_size = n_embd // n_head
    self.sa = MultiHeadAttention(n_head, head_size)
    self.ffwd = FeedForward(n_embd)
    self.ln1 = nn.LayerNorm(n_embd)
    self.ln2 = nn.LayerNorm(n_embd)

  def forward(self, x):
    x = x + self.sa(self.ln1(x))
    x = x + self.ffwd(self.ln2(x))
    return x
```

## Final Model

Putting it all together, the main model is:

```python
class GPTlite(nn.Module):

  def __init__(self, vocab_size):
    super().__init__()
    
    # vocabulary embedding and positional embedding
    self.token_embedding_table = nn.Embedding(vocab_size, n_embd)
    self.position_embedding_table = nn.Embedding(block_size, n_embd)

    #sequence of attention heads and feed forward layers
    self.blocks = nn.Sequential( *[Block(n_embd, n_head) for _ in range(n_layer)])

    #one layer normalization layer after transformer blocks
    #and one before linear layer that outputs the vocabulary
    self.ln = nn.LayerNorm(n_embd)
    self.lm_head = nn.Linear(n_embd, vocab_size, bias=False)


  def forward(self, idx):
    """ call the model with idx, for training or generation """

    #idx is of shape (B,S)
    B, S = idx.shape
    tok_emb = self.token_embedding_table(idx) #shape (B,S,E)
    pos_emb = self.position_embedding_table(torch.arange(S, device=idx.device)) #shape (S,E)
    x = tok_emb + pos_emb #shape (B,S,E)
    x = self.blocks(x)
    x = self.ln(x)
    logits = self.lm_head(x) #shape (B,S,C)
    logits = torch.swapaxes(logits, 1, 2) #shape (B,C,S) to comply with CrossEntropyLoss
    return logits
```

and the inference (token generation) function is:

```python
  def generate(self, idx, max_new_tokens):
    """ given a context idx, generate max_new_tokens tokens and append them to idx """
    for _ in range(max_new_tokens):
      idx_cond = idx[:, -block_size:] #we can never have any idx longer than block_size
      logits = self(idx_cond) #call fwd without targets
      logits = logits[:, :, -1] # take last token. from shape (B, C, S) to (B, C)
      #convert logits to probabilities
      probs = F.softmax(logits, dim=-1) # shape (B, C)
      #randomly sample the next tokens, 1 for each of the previous probability distributions
      #(one could take instead the argmax, but that would be deterministic and boring)
      idx_next = torch.multinomial(probs, num_samples=1) # shape (B, 1)
      #append next token ix to the solution sequence so far
      idx = torch.cat([idx, idx_next], dim=-1) # shape (B, S+1)
    return idx  
```


## Train loop

The model is instantiated and copied to the compute device:

```python
m  = GPTlite(vocab_size).to(device)
```

The optimizer is then initialized and the train loop is executed:

```python
# train the model
optimizer = torch.optim.Adam(m.parameters(), lr=learning_rate)
for steps in range(max_iters):
  idx, targets = get_batch(train_data)   #get a batch of training data
  logits = m(idx)   #forward pass
  loss = F.cross_entropy(logits, targets)
  loss.backward()   #backward pass
  optimizer.step()   #update parameters
  optimizer.zero_grad(set_to_none=True)  #sets to None instead of 0, to save memory

  #print progress
  if steps % 100 == 0: print(f"step {steps}, loss {loss.item():.2f}")
    
  @torch.no_grad()
  # eval loop: no backprop on this data, to avoid storing all intermediate variables
  def eval_loss():
    idx, targets = get_batch(valid_data)   #get a batch of validation data
    logits = m(idx)   #forward pass
    loss = F.cross_entropy(logits, targets)
    print(f"step {steps}, eval loss {loss.item():.2f}")
    return loss
  
  if steps % eval_interval == 0: eval_loss().item()
      
```
