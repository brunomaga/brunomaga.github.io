The [transformer](https://en.wikipedia.org/wiki/Transformer_(deep_learning_architecture)) of [Attention Is All You Need](https://arxiv.org/abs/1706.03762) (Vaswani et al., 2017) translates text with an encoder and a decoder that use attention instead of recurrence (see the [transformer post]({{ site.baseurl }}{% post_url 2020-02-28-learning-from-sequences %})). The decoder masks its attention, so that each position sees only itself and the positions before it, and predicts the next token. A stack of decoder blocks, without the encoder and the cross-attention, is a [language model](https://en.wikipedia.org/wiki/Language_model) that generates text one token at a time. [GPT-2](https://en.wikipedia.org/wiki/GPT-2) and its successors follow this design. GPTlite, a small model in the style of GPT-2, implements it in PyTorch and trains on a text of Shakespeare's plays.

## Tokenization

A tokenizer maps a text to a sequence of integers, the *tokens*, and an embedding maps each token to a vector of size $$E$$ (`n_embd`). The simplest tokenizer maps each character to an integer:

```python
# collect sorted list of input characters and create 
# string-to-int (stoi) and int-to-string (itos) representations:
chars = sorted(list(set(text)))
stoi = { ch:i for i,ch in enumerate(chars) }
itos = { i:ch for i,ch in enumerate(chars) }

# define encode and decode functions that convert strings to arrays of tokens and vice-versa
encode = lambda x: torch.tensor([stoi[ch] for ch in x], dtype=torch.long) #encode text to integers
decode = lambda x: ''.join([itos[i] for i in x]) #decode integers to text
vocab_size = len(stoi)
``` 

The vocabulary size `vocab_size` is the number of distinct tokens, here 65 characters, of which the first is the line break `\n`:

```python

!$&',-.3:;?ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz
```

A tokenizer of words or subwords has a larger vocabulary, and thus a larger embedding table and output layer. It produces fewer tokens per text: a context of `block_size` tokens covers more text, and attention, whose cost grows with the square of the sequence length, runs on fewer tokens. Examples are Google's [SentencePiece](https://github.com/google/sentencepiece), the tokenizers of [Hugging Face](https://huggingface.co/docs/transformers/tokenizer_summary), and `tiktoken`, the [byte-pair encoding](https://en.wikipedia.org/wiki/Byte-pair_encoding) (BPE) tokenizer of OpenAI's GPT models:

```python
import tiktoken
enc = tiktoken.encoding_for_model("gpt-4")
print(enc.n_vocab)
print(enc.encode("Hello world"))
print(enc.decode(enc.encode("Hello world")))
```

The output is the vocabulary size of the GPT-4 tokenizer, `100277`, the tokens of `"Hello world"`, `[9906, 1917]`, and the decoded string.

## Positional Encodings

Without a mask, attention is permutation-equivariant: permuting the input tokens permutes its outputs in the same way. The model adds a position embedding to each token embedding, so that it can use the order of the tokens. The transformer uses a fixed encoding made of sines and cosines. GPTlite learns the position embeddings instead, as GPT-2 does, with an `nn.Embedding` table of `block_size` rows. A learned table has no entry beyond position `block_size`, while the sines and cosines are defined for any position.

```python
token_embedding_table = nn.Embedding(vocab_size, n_embd)    # from tokens to embedding
position_embedding_table = nn.Embedding(block_size, n_embd) # from position to embedding
```

## Batching

The text is split into 90% training and 10% validation data:

```python
data = encode(text)  #use any encoder here
n = int(0.9*len(data))
train_data, valid_data = data[:n], data[n:]
```

The full, training and validation sets have `1115394`, `1003854` and `111540` tokens.

Each sample of a batch is a window of `block_size` consecutive tokens at a random offset, and its target is the same window shifted by one token. With the causal mask, the output at position $$t$$ sees the tokens $$0$$ to $$t$$ and predicts the token $$t+1$$. A sample thus holds `block_size` training examples, with contexts of length 1 to `block_size`:

```python
def get_batch(source):
  """ get a batch of batch_size sequences of length block_size from source """
  
  # generate `batch_size` random offsets on the data 
  ix = torch.randint(len(source)-block_size, (batch_size,) )
  # collect `batch_size` subsequences of length `block_size` from source, as data and target
  x = torch.stack([source[i:i+block_size] for i in ix])
  # target is just x shifted right (ie the predicted token is the next in the sequence)
  y = torch.stack([source[i+1:i+1+block_size] for i in ix])
  return x.to(device), y.to(device)


# test get_batch()

    context = xb[b,:t+1]
    target = yb[b,t]
    print(f"for input {context.tolist()} target is {target.tolist()}")
```

## Multi-Head Masked Attention

Row $$t$$ of an attention matrix holds the weights with which token $$t$$ averages the tokens of the sequence. The causal mask lets each token see only itself and the previous tokens, so the matrix is lower triangular. The simplest such matrix gives the same weight to all visible tokens. For a random input `x` of shape (batch, sequence, embedding):

```python
B, S, E, = 4, 8, 2
x = torch.randn(B,S,E) #shape (B,S,E)
```

The code writes the dimensions as:
- `B`, the batch size, `batch_size`;
- `S`, the sequence length, at most `block_size`;
- `E`, the embedding size, `n_embd`;
- `C`, the vocabulary size, `vocab_size`.

The uniform attention matrix is:

```python
#attention matrix (lower triangular), a mask used to only show previous items to predict next item
wei = torch.tril(torch.ones((S,S), dtype=torch.float32, device=device))
#normalize mask so that it sums to one. use keepdim to make broadcast operation work later
wei /= wei.sum(dim=1, keepdim=True)
``` 

An equivalent notation, used below, sets the masked entries to $$-\infty$$ and applies a softmax to each row:

```python
tril = torch.tril(torch.ones(S,S))
wei = wei.masked_fill(tril==0, float('-inf'))
wei = F.softmax(wei, dim=-1) #equivalent to the normalization above
```

Both give the following `wei`, whose rows sum to 1:

```python
tensor([[1.0000, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000],
        [0.5000, 0.5000, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000],
        [0.3333, 0.3333, 0.3333, 0.0000, 0.0000, 0.0000, 0.0000, 0.0000],
        [0.2500, 0.2500, 0.2500, 0.2500, 0.0000, 0.0000, 0.0000, 0.0000],
        [0.2000, 0.2000, 0.2000, 0.2000, 0.2000, 0.0000, 0.0000, 0.0000],
        [0.1667, 0.1667, 0.1667, 0.1667, 0.1667, 0.1667, 0.0000, 0.0000],
        [0.1429, 0.1429, 0.1429, 0.1429, 0.1429, 0.1429, 0.1429, 0.0000],
        [0.1250, 0.1250, 0.1250, 0.1250, 0.1250, 0.1250, 0.1250, 0.1250]])
```

The output of the attention is the matrix product of `wei` and `x`, whose row $$t$$ is the average of the tokens $$0$$ to $$t$$:

```python
out = wei @ x   # dot product shape: (B,S,S) @ (B,S,E) = (B,S,E) ie ([4, 8, 2])
```

Both `x` and `out` have the shape `[B, S, E]`, here `[4, 8, 2]`.

Self-attention computes non-uniform weights from the input. The transformer paper defines the multi-head attention as:

$$
\mathrm{MultiHead}(Q, K, V) = \mathrm{Concat}(\mathrm{head}_1, \dots, \mathrm{head}_h) \, W^O
$$

$$
\text{where } \mathrm{head}_i = \mathrm{Attention}(Q W^Q_i, K W^K_i, V W^V_i)
$$

$$
\text{and } \mathrm{Attention}(Q, K, V) = \mathrm{softmax}\left( \frac{Q K^T}{\sqrt{d_k}} \right) V
$$

where $$h$$ is the number of heads, `n_head`, and $$d_k$$ is the size of a head, `head_size`. In self-attention, $$Q$$, $$K$$ and $$V$$ are all the input `x`.

<img width="24%" height="24%" src="{{ site.assets }}/gptlite/gptlite_attention.svg"/>

{: .caption}
The multi-head attention module in the GPTlite model, emphasized in red. Adapted from [Attention is all you need](https://arxiv.org/abs/1706.03762).

The projections $$W^Q$$, $$W^K$$ and $$W^V$$ of a head are linear layers without bias:

```python
head_size=4
key   = nn.Linear(E, head_size, bias=False) 
query = nn.Linear(E, head_size, bias=False)
value = nn.Linear(E, head_size, bias=False)
```

The scaled scores $$Q K^T / \sqrt{d_k}$$ are:

```python
k = key(x) #shape (B,S, head_size)
q = query(x) #shape (B,S, head_size)
wei = q @ k.transpose(-2, -1) #shape (B,S, head_size) @ (B,head_size,S) = (B,S,S)
wei *= head_size**-0.5 #scale by sqrt(d_k) as per paper, so that variance of the wei is 1
```

The mask and the softmax of the uniform case then turn the scores into weights, which average the values `v`:

```python
tril = torch.tril(torch.ones(S,S))
wei = wei.masked_fill(tril==0, float('-inf')) #tokens only "talk" to previous tokens
wei = F.softmax(wei, dim=-1) #equivalent to the normalization above (-inf in upper diagonal will be 0)
v = value(x) # shape (B,S, head_size)
out = wei @ v # shape (B,S,S) @ (B,S,head_size) --> (B,S,head_size)
```

The weights now differ per query and depend on the input, through the learned projections: each token gives more weight to the tokens that matter to it, instead of the same weight to all. For independent query and key components with zero mean and unit variance, the dot product of a query and a key has the variance $$d_k$$, and the scaling by $$1/\sqrt{d_k}$$ brings it back to 1. Without the scaling, the softmax of the large scores is close to a one-hot vector, and its gradients are close to zero.

In cross-attention, the queries come from one sequence, and the keys and the values from another, such as the output of an encoder. GPTlite has no encoder, so it uses only self-attention. Attention never mixes the samples of a batch. Models that encode or classify a whole sequence, e.g. for sentiment analysis, use no mask, so that every token sees all tokens. Other masks fit other tasks, e.g. a band around the diagonal lets each token see only its neighbours.

The `Head` module computes one head. `MultiHeadAttention` runs `n_head` heads, concatenates their outputs, and maps them back to size $$E$$ with the projection $$W^O$$ (`proj`):

```python
class Head(nn.Module):

  def __init__(self, head_size):
    super().__init__()
    self.key   = nn.Linear(n_embd, head_size, bias=False)
    self.query = nn.Linear(n_embd, head_size, bias=False)
    self.value = nn.Linear(n_embd, head_size, bias=False)
    self.head_size = head_size
    self.register_buffer('tril', torch.tril(torch.ones(block_size, block_size)))
    self.dropout = nn.Dropout(dropout)
    #Note: this dropout randomly prevents some tokens from communicating with each other

  def forward(self, x):
    B,S,_ = x.shape
    k = self.key(x) #shape (B,S, head_size)
    q = self.query(x) #shape (B,S, head_size)
    v = self.value(x) #shape (B,S, head_size)

    #compute self-attention scores
    wei = q @ k.transpose(-2, -1) #shape (B,S, head_size) @ (B,head_size,S) --> (B,S,S)
    wei *= self.head_size**-0.5 #scale by sqrt(d_k) as per paper, so that variance of the wei is 1
    wei = wei.masked_fill(self.tril[:S,:S]==0, float('-inf')) # (B,S,S)
    wei = F.softmax(wei, dim=-1) # (B, S, S)
    wei = self.dropout(wei)

    #perform weighted aggregation of values
    out = wei @ v # (B, S, S) @ (B, S, head_size) --> (B, S, head_size)
    return out
```

```python
class MultiHeadAttention(nn.Module):
  """ Multi-head attention as a collection of heads with concatenated outputs."""
  def __init__(self, num_heads, head_size):
    super().__init__()
    self.heads = nn.ModuleList([Head(head_size) for _ in range(num_heads)])
    self.proj  = nn.Linear(head_size*num_heads, n_embd) # combine all head outputs
    self.dropout = nn.Dropout(dropout)

  def forward(self, x):
    out = torch.cat([head(x) for head in self.heads], dim=-1)
    out = self.proj(out)
    out = self.dropout(out)
    return out
```

## Feed-Forward Network

The feed-forward network (FFN) of each block is a neural network with one hidden layer of size $$4E$$ and a ReLU activation, applied to each token separately:

```python
class FeedForward(nn.Module):
  """ the feed forward network (FFN) in the paper"""

  def __init__(self, n_embd):
    super().__init__()
    # Note: in the paper (section 3.3) we have d_{model}=512 and d_{ff}=2048.
    # Therefore the inner layer is 4 times the size of the embedding layer
    self.net = nn.Sequential(
        nn.Linear(n_embd, n_embd*4),
        nn.ReLU(),
        nn.Linear(n_embd*4, n_embd),
        nn.Dropout(dropout)
      )

  def forward(self, x):
    return self.net(x)
```

## The GPT Block

A GPT block applies a multi-head attention and then an FFN. Each of the two has a [residual connection](https://en.wikipedia.org/wiki/Residual_neural_network), which adds its input to its output, so that the gradients flow through a deep stack of blocks. The transformer paper applies the [layer normalization](https://en.wikipedia.org/wiki/Normalization_(machine_learning)#Layer_normalization) after the residual addition, $$\mathrm{LayerNorm}(x + \mathrm{Sublayer}(x))$$ (post-norm). GPT-2 and most later models apply it to the input of each sublayer, $$x + \mathrm{Sublayer}(\mathrm{LayerNorm}(x))$$ (pre-norm), and add a layer normalization after the last block. With pre-norm, the gradients are well behaved at initialization, and training reaches comparable results without the learning-rate warm-up that post-norm needs ([On Layer Normalization in the Transformer Architecture](https://arxiv.org/abs/2002.04745), Xiong et al., 2020). GPTlite uses pre-norm:

```python
class Block(nn.Module):
  """ Transformer block: communication (attention) followed by computation (FFN) """

  def __init__(self, n_embd, n_head):
    # n_embd: embedding dimension
    # n_head: the number of heads we'd like to use
    super().__init__()
    head_size = n_embd // n_head
    self.sa = MultiHeadAttention(n_head, head_size)
    self.ffwd = FeedForward(n_embd)
    self.ln1 = nn.LayerNorm(n_embd)
    self.ln2 = nn.LayerNorm(n_embd)

  def forward(self, x):
    x = x + self.sa(self.ln1(x))
    x = x + self.ffwd(self.ln2(x))
    return x
```

## Final Model

The model sums the token and the position embeddings, applies the `n_layer` blocks and the final layer normalization, and maps each position to `vocab_size` logits with a linear layer:

```python
class GPTlite(nn.Module):

  def __init__(self, vocab_size):
    super().__init__()
    
    # vocabulary embedding and positional embedding
    self.token_embedding_table = nn.Embedding(vocab_size, n_embd)
    self.position_embedding_table = nn.Embedding(block_size, n_embd)

    #sequence of attention heads and feed forward layers
    self.blocks = nn.Sequential( *[Block(n_embd, n_head) for _ in range(n_layer)])

    #one layer normalization layer after transformer blocks
    #and one before linear layer that outputs the vocabulary
    self.ln = nn.LayerNorm(n_embd)
    self.lm_head = nn.Linear(n_embd, vocab_size, bias=False)


  def forward(self, idx):
    """ call the model with idx, for training or generation """

    #idx is of shape (B,S)
    B, S = idx.shape
    tok_emb = self.token_embedding_table(idx) #shape (B,S,E)
    pos_emb = self.position_embedding_table(torch.arange(S, device=idx.device)) #shape (S,E)
    x = tok_emb + pos_emb #shape (B,S,E)
    x = self.blocks(x)
    x = self.ln(x)
    logits = self.lm_head(x) #shape (B,S,C)
    logits = torch.swapaxes(logits, 1, 2) #shape (B,C,S) to comply with CrossEntropyLoss
    return logits
```

Generation feeds the last `block_size` tokens to the model, converts the logits of the last position into probabilities with a softmax, samples the next token, and appends it to the sequence:

```python
  def generate(self, idx, max_new_tokens):
    """ given a context idx, generate max_new_tokens tokens and append them to idx """
    for _ in range(max_new_tokens):
      idx_cond = idx[:, -block_size:] #we can never have any idx longer than block_size
      logits = self(idx_cond) #call fwd without targets
      logits = logits[:, :, -1] # take last token. from shape (B, C, S) to (B, C)
      #convert logits to probabilities
      probs = F.softmax(logits, dim=-1) # shape (B, C)
      #randomly sample the next tokens, 1 for each of the previous probability distributions
      #(one could take instead the argmax, but that would be deterministic and boring)
      idx_next = torch.multinomial(probs, num_samples=1) # shape (B, 1)
      #append next token ix to the solution sequence so far
      idx = torch.cat([idx, idx_next], dim=-1) # shape (B, S+1)
    return idx  
```

## Training Loop

The model is created on the compute device:

```python
m  = GPTlite(vocab_size).to(device)
```

Training runs the Adam optimizer on the cross-entropy loss of the next token, and computes the loss of a validation batch every `eval_interval` steps:

```python
# train the model
optimizer = torch.optim.Adam(m.parameters(), lr=learning_rate)
for steps in range(max_iters):
  idx, targets = get_batch(train_data)   #get a batch of training data
  logits = m(idx)   #forward pass
  loss = F.cross_entropy(logits, targets)
  loss.backward()   #backward pass
  optimizer.step()   #update parameters
  optimizer.zero_grad(set_to_none=True)  #sets to None instead of 0, to save memory

  #print progress
  if steps % 100 == 0: print(f"step {steps}, loss {loss.item():.2f}")
    
  @torch.no_grad()
  # eval loop: no backprop on this data, to avoid storing all intermediate variables
  def eval_loss():
    idx, targets = get_batch(valid_data)   #get a batch of validation data
    logits = m(idx)   #forward pass
    loss = F.cross_entropy(logits, targets)
    print(f"step {steps}, eval loss {loss.item():.2f}")
    return loss
  
  if steps % eval_interval == 0: eval_loss().item()
      
```

GPT-3 ([Language Models are Few-Shot Learners](https://arxiv.org/abs/2005.14165), Brown et al., 2020) is a decoder-only transformer with 96 blocks, $$E = 12288$$, 96 heads, a context of 2048 tokens and 175 billion parameters. GPTlite covers only pre-training. A chat model adds three training steps: supervised fine-tuning, reward modeling, and reinforcement learning with PPO ([Proximal Policy Optimization Algorithms](https://arxiv.org/abs/1707.06347), Schulman et al., 2017), as in [Training language models to follow instructions with human feedback](https://arxiv.org/abs/2203.02155) (Ouyang et al., 2022). The talk [State of GPT](https://www.youtube.com/watch?v=bZQun8Y4L2A) gives an overview of the four steps.

The code follows the [tutorial video](https://www.youtube.com/watch?v=kCc8FmEb1nY) of Andrej Karpathy, whose [nanoGPT repo](https://github.com/karpathy/nanoGPT) trains GPT-2 models. The [GPTlite repo](https://github.com/{{ site.repository }}/tree/master/assets/gptlite) holds an extended version of the code: one projection computes all the heads at once, and `main.py` clips the gradients and evaluates the model without dropout.
